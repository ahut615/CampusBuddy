### 6.4 核心数据流

```
用户操作 → React 页面 → api/xx.ts (axios) → FastAPI 路由
    → deps.get_current_user_id()（解析 JWT）
    → 业务逻辑（CRUD + 权限校验）
    → 数据库读写
    → 返回 {code, message, data} → 前端渲染
```

## 八、API 接口规范

### 8.1 统一返回格式

**所有接口**都使用 `app/utils/response.py` 中的工具函数：

```python
# response.py
from typing import Any, Optional

def ok(message: str = "success", data: Any = None) -> dict:
    return {"code": 200, "message": message, "data": data or {}}

def err(code: int, message: str) -> dict:
    return {"code": code, "message": message, "data": {}}
```

**返回格式示例：**

```json
// 成功
{ "code": 200, "message": "登录成功", "data": { "token": "eyJ...", "user": {...} } }

// 失败
{ "code": 401, "message": "密码错误", "data": {} }
```

### 8.2 HTTP 状态码约定

| code | 含义 | 场景 |
|------|------|------|
| 200 | 成功 | 所有正常返回 |
| 400 | 请求参数错误 | 字段校验失败、数据不合法 |
| 401 | 未认证 | Token 缺失/过期/无效 |
| 403 | 无权限 | 不是自己的资源却尝试修改 |
| 404 | 资源不存在 | 需求/申请/用户找不到 |
| 409 | 资源冲突 | 重复申请、重复注册 |
| 500 | 服务器错误 | 未知异常 |

### 8.3 认证机制

```
请求头: Authorization: Bearer <JWT_TOKEN>

JWT 载荷:
{
  "sub": "1",        // user.id 转字符串
  "exp": 1700000000  // 过期时间戳
}
```

**前端发送请求：** `api/client.ts` 中的 axios 拦截器自动从 `localStorage('token')` 读取 token 并附加到每个请求头。成员A完成登录模块后，token 存入逻辑自动生效，其余成员无需关心。

**后端验证：** 在需要登录的接口参数中声明 `current_user_id: int = Depends(get_current_user_id)`，FastAPI 会自动完成 JWT 解析和用户验证。

**PUT /applications/{id} 审核逻辑：**
1. 验证操作者是需求发布者

### 8.6 权限判断速查表

| 操作 | 权限规则 | 代码 |
|------|----------|------|
| 修改/删除需求 | `post.user_id == current_user_id` | 在路由中手动校验 |
| 审核申请 | Post 的 `user_id == current_user_id` | 先查 Post 再比较 |
| 标记通知已读 | `notification.user_id == current_user_id` | 在路由中手动校验 |
| 不能申请自己的需求 | `post.user_id != current_user_id` | 创建申请时校验 |
| 不能重复申请 | 同一个 (post_id, applicant_id) 不能重复 | 数据库唯一约束兜底 |

### 9.3 API 调用层规范

```typescript
// frontend/src/api/client.ts — axios 实例（公共文件，成员A 搭建）
import axios from 'axios';

const client = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || 'http://localhost:8000',
  timeout: 10000,
});

// 请求拦截器：自动带 token
client.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// 响应拦截器：统一错误处理
client.interceptors.response.use(
  (res) => res,
  (err) => {
    if (err.response?.status === 401) {
      localStorage.removeItem('token');
      window.location.href = '/login';
    }
    return Promise.reject(err);
  }
);

export default client;
```

import { create } from 'zustand';

interface AuthState {

  user: User | null;
  setToken: (token: string) => void;
  setUser: (user: User) => void;
  logout: () => void;
}

  token: localStorage.getItem('token'),
  user: null,

    localStorage.setItem('token', token);
    set({ token });
  },
  setUser: (user) => set({ user }),

  },
}));

### 10.1 CC 工作原理

Claude Code 是一个 CLI 工具，能直接读取项目文件、编辑代码、运行命令。你不需要逐行告诉它怎么写——描述**目标 + 约束 + 上下文**，它会自己找到正确的文件、读懂现有代码、在已有模式上扩展。

```
你说：实现 POST /posts 接口
CC 做：
  1. 读 models/post.py 了解表结构
  2. 读 schemas/post.py 了解请求格式
  3. 读 core/deps.py 了解认证方式
  4. 读 utils/response.py 了解返回格式
  5. 参考 api/auth.py 的风格
  6. 在 api/post.py 中写出完整代码
  7. 在 main.py 中注册路由
```

## 十三、常见问题与排错（FAQ）

### Q1: `pip install` 报错找不到包
```bash
# 确保在项目根目录下，使用正确的 requirements.txt
cd backend
pip install -r requirements.txt
# 如果还报错，检查 Python 版本 ≥ 3.10
python --version
```

### Q2: `npm install` 很慢或失败
```bash
# 使用国内镜像
npm config set registry https://registry.npmmirror.com
npm install
```

### Q3: 后端启动报 `ModuleNotFoundError: No module named 'app'`
```bash
# 确保在 backend/ 目录下启动
cd backend
uvicorn app.main:app --reload
# 不要在 CampusBuddy/ 根目录启动
```

### Q4: 前端 API 请求全部 401
```bash
# 检查：
# 1. 是否已登录（localStorage 中有没有 token）
# 2. 后端是否在 8000 端口运行
# 3. VITE_API_BASE_URL 环境变量是否正确
# 4. 浏览器 F12 → Network → 请求头里有没有 Authorization
```

### Q5: Swagger 文档能调通但前端报 CORS 错误
```bash
# 检查 backend/app/main.py 中是否配置了 CORS：
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],  # 前端地址
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

### Q6: `shadcn-ui add` 命令失败
```bash
# 确保在 frontend/ 目录下运行
cd frontend
# 确保已初始化 shadcn（检查 components.json 是否存在）
# 如未初始化：
npx shadcn-ui@latest init
# 然后重新 add
```

### Q7: Docker 启动后前端页面空白
```bash
# 检查：
# 1. nginx 配置的前端静态文件路径是否正确
# 2. 前端 build 是否成功：cd frontend && npm run build
# 3. docker-compose 中 nginx 的 volumes 映射是否正确
# 4. docker compose logs frontend 查看 nginx 日志
```

### Q8: 数据库表不存在
```bash
# 首次启动时，确保 main.py 中有建表逻辑：
# app.database.Base.metadata.create_all(bind=engine)
# 或在启动事件中调用

# 如果用的是 alembic：
cd backend && alembic upgrade head
```

### Q9: 合并 develop 后代码不能运行
```bash
# 1. 先确认自己的分支之前是能运行的
# 2. 查看 main.py 和 App.tsx，是否保留了所有人的路由注册
# 3. 检查 package.json 和 requirements.txt 是否合并正确
# 4. 重新安装依赖：npm install && pip install -r requirements.txt
```

### Q10: git push 被拒绝
```bash
# 原因：其他人刚刚推了你的分支
# 解决：
git pull origin feature-auth --rebase
# 解决冲突后：
git push origin feature-auth
# 严禁使用 --force 推共用分支！
```
